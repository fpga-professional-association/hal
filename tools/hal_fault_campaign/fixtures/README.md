# The fault-campaign fixture

Four files, and the relationship between them is the point.

| file | what it is |
| --- | --- |
| `parity_counter.v` | a hand-written flat gate-level netlist against `plugins/gate_libraries/definitions/example_library.hgl` — nine registers with three deliberately different fates |
| `reference_model.py` | an **independent** cycle model of that Verilog: eight lines of next-state logic, the same fault model, no HAL |
| `ground_truth.json` | generated by the model: the fault-free baseline, all 36 faulty traces and the expected verdict of every fault under both shipped windows |
| `campaign_short_window.json`, `campaign_long_window.json` | the two shipped campaigns — the same faults over the same workload, judged over one cycle and over four |

Nothing in `ground_truth.json` came from HAL. That is what makes it ground
truth: `tests/headless_smoke/fault_campaign_smoke.py` requires HAL's simulation
of `parity_counter.v` to reproduce these traces *cycle by cycle*, so a
disagreement is a real finding about one of the two and not a test that adapted
to whatever the simulator did.

## The design

```
                       ┌─────────────────────────────┐
   RST ────────────────┤ CNT_reg_0..2  (3-bit up)    ├──▶ CNT0..CNT2
                       │ PAR_reg = parity(next CNT)  │
                       └──────────────┬──────────────┘
                                      └── ERR = PAR ^ CNT0 ^ CNT1 ^ CNT2  ──▶ ERR

   ────────────────────  AUX_reg (toggle) ──────────────────────────────▶ AUX_O

   PIPE_IN ──▶ PIPE_reg_0 ─▶ PIPE_reg_1 ─▶ PIPE_reg_2 ─▶ PIPE_reg_3 ───▶ PIPE_O
```

`ERR` is 0 in every fault-free cycle, because `PAR_reg` is loaded with the parity
of the counter value the counter is about to hold. A flip in any of the four
protected registers breaks that equality in the very cycle it happens, so the
detector fires with latency 0 — and stops firing one cycle later, once the parity
register has been reloaded from the (now corrupted) counter. That is a real and
uncomfortable property of a combinational parity check, and a campaign whose
observation window misses the injection cycle would classify a perfectly
detectable fault as unobserved. The two shipped windows exist to make that kind
of thing visible rather than to hide it.

`AUX_reg` is a toggle with no checker. A flip inverts its whole future sequence —
but not the cycle it happens in, because the register's next state is the inverse
of its own (corrupted) output and the two inversions cancel at the sample point.
Divergence therefore starts one cycle later, which is exactly the sort of detail
a hand-waved expectation gets wrong and a model does not.

`PIPE_reg_0..3` is a four-deep shift register. A flip in stage *k* reaches
`PIPE_O` after `3-k` cycles, so the first two stages are unobserved in a
one-cycle window and externally observable in a four-cycle one. Same fault, same
trace, different window.

Every register is an `FFR` with its async reset on `RST`: driven through
`NetlistSimulatorController` there is no way to preload sequential state
(`initialize_sequential_gates` is not exposed on the controller), so without the
reset in cycle 0 every register would start at X and every trace would be
undefined.

## Expected results, 9 registers × cycles 3–6

| window | faults | detected | silent divergence | unobserved | indeterminate |
| --- | --- | --- | --- | --- | --- |
| 1 cycle (`campaign_short_window.json`, exhaustive) | 36 | 16 | 8 | 12 | 0 |
| 4 cycles (all 36, for reference) | 36 | 16 | 20 | 0 | 0 |
| 4 cycles (`campaign_long_window.json`, seed 20260907) | 12 | 7 | 5 | 0 | 0 |

The sampled campaign draws `AUX_reg@3`, `AUX_reg@4` and `PIPE_reg_1@4` — three
faults the one-cycle window calls unobserved and the four-cycle window calls
externally observable, undetected corruption.

Detection latency is 0 for every detected fault. Divergence latency is 0 for the
last two pipeline stages, 1 for `AUX_reg` and `PIPE_reg_1`, and 2 for
`PIPE_reg_0`.

## Regenerating

```bash
python tools/hal_fault_campaign/fixtures/reference_model.py --write
```

The unit tests assert that the committed `ground_truth.json` is byte-equal to a
fresh generation, so an edit to the model that is not regenerated fails the
suite instead of drifting.
