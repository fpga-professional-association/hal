# Fixtures and their ground truth

Everything in this directory is checked in, and everything except `ice40_mixed.v`
and this file is regenerated by:

```bash
python tools/hal_migration/fixtures/_generate.py
```

The unit tests fail if a generated file is stale, so the ground truth below and
the files never drift apart silently.

Regenerate on a checkout with LF line endings (the build/verification container
and CI both have one). The inventory records the SHA-256 of
`plugins/gate_libraries/definitions/ice40ultra.hgl`, and that file lives outside
this directory, so the `-text` attribute in `.gitattributes` here cannot pin it:
on a Windows checkout with `core.autocrlf=true` its bytes -- and therefore its
hash -- differ from the committed content.

| file | what it is |
| --- | --- |
| `ice40_mixed.v` | hand-written iCE40 UltraPlus netlist, parsed with `plugins/gate_libraries/definitions/ice40ultra.hgl` |
| `ice40_mixed_inventory.json` | the `source-inventory-1.0.0` document for it |
| `ice40_mixed_assessment.json` | the `hal_findings` assessment against `catalogues/ice40ultra-to-generic-fpga-1.0.0.json` |
| `ice40_mixed_report.md` | the Markdown assessment report |
| `incomplete_metadata_inventory.json` | a second inventory whose metadata is deliberately missing |
| `stub_netlist.py` | builds a netlist-shaped stub from a real `.hgl`, so the extractor can be tested without a HAL build |

## `ice40_mixed.v`

Not a working design: each instance exists to put one kind of migration
question into the inventory. Ground truth, as read from `ice40ultra.hgl`:

* **19 gates, 15 gate types, 98 nets**
* **2 clock nets**: `clk_g` (driven by `SB_GB`, 10 clock-pin sinks) and
  `osc_clk` (driven by the `SB_HFOSC` output, which HAL types as a `clock` pin,
  1 sink). Note that `clk_pin` is *not* a clock signal: the input pin of `SB_GB`
  has pin type `none`, so HAL cannot know what it carries -- and the tool does
  not guess.
* **1 reset net**: `rst`, 4 sinks (`SB_DFFR` x2, `SB_DFFSR`, `SB_DFFNSR`)
* **35 top-level ports**: 32 inputs (`clk_pin`, `rst`, `d_in`, `ce`, `i2c_scl`,
  `ram_addr[10:0]`, `ram_wdata[15:0]`), 2 outputs (`q_out`, `i2c_sda_out`) and
  one `inout` (`pad`). An `inout` port is one port, not one input plus one output.
* **13 metadata gaps**

| gate type | count | category (from properties) | expected mapping | why |
| --- | --- | --- | --- | --- |
| `SB_LUT4` | 2 | combinational | supported | 4-LUT into a 6-LUT; INIT bit order is an obligation |
| `SB_DFF` | 3 | register | supported | plain rising-edge flip-flop |
| `SB_DFFE` | 1 | register | supported | clock enable is in the next-state function |
| `GND` | 1 | constant | supported | constant driver |
| `VCC` | 1 | constant | supported | constant driver |
| `SB_DFFR` | 2 | register | candidate | library models `R` with `clear_on` (asynchronous clear) |
| `SB_DFFSR` | 1 | register | candidate | reset folded into the next-state function, i.e. synchronous |
| `SB_CARRY` | 1 | arithmetic | candidate | carry conventions differ; re-infer the arithmetic |
| `SB_MAC16` | 1 | arithmetic | candidate | DSP configuration is not in the netlist |
| `SB_IO` | 1 | io | candidate | the buffer maps, the constraints do not |
| `SB_GB` | 1 | combinational | candidate | a buffer substitution is not a clocking plan |
| `SB_DFFNSR` | 1 | register | **unresolved** | negative-edge family is deliberately absent from the catalogue |
| `SB_RAM40_4K` | 1 | memory | **unresolved** | catalogue says `candidate`, but the mapping requires `bit_size` and `ram_ports` and the gate library models neither -> downgraded |
| `SB_HFOSC` | 1 | combinational | **unresolved** | no on-chip oscillator in the target profile |
| `SB_I2C` | 1 | sequential_other | **unresolved** | hard IP with no generic equivalent |

Expected assessment totals: **5 supported, 6 candidate, 4 unresolved** gate
types (8 / 7 / 4 gate instances), 20 distinct verification obligations, none of
them discharged.

Two categorisations are worth reading twice, because they are properties of the
gate library rather than of the primitive's reputation:

* `SB_GB` and `SB_HFOSC` are `combinational` -- the library gives them no
  clocking property, so the inventory does not invent one;
* `SB_I2C` is `sequential_other`: marked sequential, but with no flip-flop,
  latch or RAM component, so its state behaviour is not described at all.

## `incomplete_metadata_inventory.json`

A hand-written inventory standing for a netlist read with a gate library that
describes far less than the design needs: no pin types, no LUT component, no RAM
component, and one gate type (`CUSTOM_HARD_BLOCK`) with no properties at all.

Expected assessment: **0 supported, 0 candidate, 4 unresolved**. `SB_DFF`,
`SB_LUT4` and `SB_RAM40_4K` are downgraded because the metadata their mappings
require is absent, and `CUSTOM_HARD_BLOCK` is unresolved because a black box has
no source behaviour a target could be compared against.

## Checking the ground truth against a real HAL

`test_hal_migration_hal.py` parses `ice40_mixed.v` with the real bindings and
compares gate types, counts, categories, pin metadata, clock/reset signals and
I/O ports against `ice40_mixed_inventory.json`. If HAL and this directory ever
disagree, the fixture is wrong.

Those tests need HAL's parsers, which are plugins: a run that does not call
`halenv.load_all_plugins()` first has no parser registered for `.v` or `.hgl`
and fails to load a perfectly valid netlist.
