## 2. `example_inputs.vcd`

### 2.1 Header oddities / planted text

```
$date      Sat Dec 31 23:59:60 2016            <- a real leap second (the last one to date)
$version   Leave no stone unturned! But for this file, consider looking at it
           in a waveform viewer instead.
$timescale 1ps
$comment   Show the parameter values. $end     <- placed AFTER $enddefinitions
```

* `23:59:60` is a valid UTC leap-second timestamp, not a typo — flavour, plus a nudge
  that odd-looking details are intentional.
* `$date` / `$version` / `$comment` and the `$dumpall`-with-no-body block are lifted
  almost verbatim from the sample VCD in the IEEE 1364 LRM. "Show the parameter values."
  is boilerplate from that sample, **not** an extra puzzle layer; taken at face value in
  a viewer it means *display the bus values*, i.e. render `O[7:0]` as ASCII to read
  `TRY AGAIN`.
* Each of the six variables is wrapped in its own redundant `$scope module puzzle …
  $upscope` pair (six identical scopes) — cosmetic, but it is what makes `O` show up as
  `puzzle.O` in Surfer.
* The file is 8438 bytes, pure 7-bit ASCII, LF line endings, no trailing garbage, no
  non-printable bytes, no steganography in whitespace. Nothing is hidden in the body
  beyond the stimulus itself.

### 2.2 Clocking and reset protocol

* `clk` period **10 000 ps (10 ns, 100 MHz)**, 50 % duty. First rising edge at t = 5 000 ps.
  312 rising edges total (t = 5 000 … 3 115 000 ps).
* All stimulus (`rst_n`, `enable`, `I`) changes **on the falling edge** of `clk`
  (t ≡ 0 mod 10 000 ps) and is therefore sampled cleanly on the following rising edge.
* `O[7:0]` and `success` change **on the rising edge** (t ≡ 5 000 mod 10 000 ps), i.e.
  they are registered outputs.
* Power-up: `O = x`, `success = x` until the first rising edge, then `O = 0x00`,
  `success = 0`.

Timeline of the two complete attempts:

| t (ps) | event |
|---|---|
| 0 | `clk=0 rst_n=0 enable=0 I=0` |
| 5 000 / 15 000 / 25 000 | 3 rising edges taken **with `rst_n` low** |
| 30 000 | `rst_n → 1` (on a falling edge) |
| 35 000 | 1 idle rising edge with `rst_n=1, enable=0` |
| 40 000 | `enable → 1` |
| 45 000 … 1 245 000 | **121 rising edges with `enable = 1`** — the payload |
| 1 250 000 | `enable → 0` |
| 1 255 000 … 1 345 000 | 10 rising edges: `O` walks `T R Y ␠ A G A I N \0` (one char per clock) |
| 1 350 000 … 1 555 000 | idle, `O = 0x00` |
| 1 560 000 | `rst_n → 0` |
| 1 565 000 / 1 575 000 / 1 585 000 | 3 rising edges with `rst_n` low (identical reset recipe) |
| 1 590 000 | `rst_n → 1` |
| 1 600 000 | `enable → 1` **and** `I → 1` on the same falling edge |
| 1 605 000 … 2 805 000 | **121 rising edges with `enable = 1`** — second payload |
| 2 810 000 | `enable → 0` |
| 2 815 000 … 2 905 000 | `O` walks `T R Y ␠ A G A I N \0` again |
| 2 910 000 … 3 115 000 | idle clocking, `success` stays 0 |

So the black-box contract is:

1. Hold `rst_n = 0` for ≥ 3 clocks, release it with `enable = 0`.
2. Raise `enable` and shift 121 bits into `I`, one bit per rising edge, MSB of the
   stream first in time.
3. Drop `enable`. Starting on the **next** rising edge the design emits 10 bytes on
   `O[7:0]`, one per clock (`TRY AGAIN\0` for a wrong guess). `success` is expected to
   go high for the correct guess.
4. The whole sequence is re-runnable by pulsing `rst_n` again.

### 2.3 Decoding the 121-bit payload  ← the important part

The 121 bits are **11 characters × an 11-clock frame**:

* bits 0–7 of each frame = one 8-bit character, **LSB first**
* bits 8–10 of each frame = 3 idle-low clocks (always `000`; equivalently the character
  is 7-bit ASCII followed by 4 zeros)

An exhaustive search over frame length 8…16, offset 0…3, LSB/MSB-first and
byte-at-head/tail finds exactly **one** framing that yields printable ASCII with an
all-zero pad, and it is the same framing in both windows:

```
window 0 (t = 45 000 ps,   121 bits): 'The night s'
window 1 (t = 1 605 000 ps, 121 bits): 'ky awaits  '
                                 --> 'The night sky awaits  '
```

Raw bit strings (time order, first bit sampled = leftmost), 38 ones each:

```
w0 0010101000000010110000101001100000000010000001110110000100101100001110011000000010110000001011100000000010000011001110000
w1 1101011000010011110000000001000001000011000011101110000100001100001001011000000101110000110011100000000010000000000100000
```

Folded to 11 × 11 the frame structure is obvious (columns 7–10 are never set):

```
w0                w1
..#.#.#....       ##.#.##....
...#.##....       #..####....
#.#..##....       .....#.....
.....#.....       #....##....
.###.##....       ###.###....
#..#.##....       #....##....
###..##....       #..#.##....
...#.##....       ..#.###....
..#.###....       ##..###....
.....#.....       .....#.....
##..###....       .....#.....
```

**Implication for the real solve:** the correct answer is an 11-character ASCII string,
serialised LSB-first with 3 idle clocks between characters, 121 clocks total, sent while
`enable` is high after a 3-cycle reset. Both hint messages point at the night sky /
stars, so guess space is "an 11-character astronomy word or phrase".

## 3. `puzzle.gds` — layer 200/0 morse

* Library `LIB`, unit 1e-6, precision 1e-9. One top cell `puzzle`,
  bbox `(0, −52.72) … (200, 300)` µm. 81 cells total.
* Two marker cells exist purely to carry layer **200/0** (a non-manufacturing,
  non-sky130 layer number — i.e. an annotation layer the authors invented):
  * `INTERNAL_3` — 1.38 × 2.72 µm, one rectangle → **dot**
  * `INTERNAL_7` — 4.14 × 2.72 µm, one rectangle → **dash** (exactly 3 × 1.38)
* 36 instances (21 dots + 15 dashes), **all** at y = −52.72 µm — i.e. in a single strip
  *below* the die area (y < 0), which is why it is invisible in `layout.png`.
  All instances: rotation 0, no x-reflection, magnification 1.
* Pitch is an exact multiple of the 1.38 µm morse time unit. Gaps between elements are
  1.38 µm (1 unit, intra-character), 4.14 µm (3 units, inter-character) or
  9.66 µm (7 units, inter-word) — textbook international morse timing.

## 6. Open questions / caveats

* `Show the parameter values.` is LRM-sample boilerplate in my reading; if the authors
  meant it literally there are no `$var parameter` entries in the file to show, so
  nothing is lost.
* The two hint phrases (`PER ARENAM AD ASTRA`, `The night sky awaits`) constrain the
  answer to an 11-character astronomy-flavoured string, but do **not** give it. The
  actual key has to come from reverse-engineering the comparator logic.
* The 3 pad clocks per character are always low in the example. Whether the DUT ignores
  `I` during them or the 11-clock frame is a property of the shift chain (e.g. an
  11-stage feed per character) is not determined from the VCD alone — check the netlist.
* Marker geometry was read from `gdstk` reference origins; all transforms are identity
  here (rot 0, no reflection, mag 1), so no transform composition was needed. Scripts
  still print rotation/reflection/magnification per instance so a different file with
  mirrored markers would be caught.
