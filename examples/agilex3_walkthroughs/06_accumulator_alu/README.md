# 06 — accumulator ALU (Agilex 3 reverse-engineering walkthrough)

**Open [`guide.html`](guide.html) in a browser.** It is the deliverable: a
step-by-step walk from a synthesized Altera Agilex 3 netlist back to RTL, with
every command, every diagram and every piece of reasoning written out.

The emphasis of this one is **arithmetic recognition**: finding the carry chain,
proving a cell is a full adder, recovering the opcode decode, and spotting the
`a - b == a + ~b + 1` trick that lets one adder do both add and subtract.

## What is here

| path | what it is |
| --- | --- |
| `design.v` | the original RTL — the answer key, not an input to the analysis |
| `spec.md` | what the design is supposed to do |
| `synth/` | the Quartus project (`.qpf`, `.qsf`) and `run_synth.sh` that produced the netlist |
| `netlist/accumulator_alu.vo` | the Quartus Prime Pro 26.1 post-synthesis Verilog export |
| `netlist/netlist.hal.v` | the same netlist rewritten by `tools/hal_agilex import` so HAL's Verilog front end can read it |
| `netlist/accumulator_alu_sclr_variant.vo` | the same design synthesized *without* `ALLOW_SYNCH_CTRL_USAGE OFF`, kept to show what falls out of the modelled primitive coverage |
| `analyze.py` | every HAL analysis step, in order; produced everything in `artifacts/` |
| `artifacts/` | the raw outputs the guide quotes |
| `images/` | the diagrams the guide embeds, all generated by `tools/hal_viz` |
| `recovered.v` | the design as reverse-engineered from the netlist alone |
| `recovered_reference.py` | the same claim as an executable model, checked against the export |
| `check.py` | headless re-assertion of the guide's claims, for CI |

## A note on `.gitignore`

`examples/.gitignore` ignores everything by default and un-ignores the shipped
`*.zip` archives one by one — the same "require an explicit add" policy
`plugins/gate_libraries/definitions/` uses. Everything in this directory was
therefore committed with `git add -f`, which is the explicit add that policy
asks for. Tracked files stay tracked, so a fresh checkout has all of this; only
*new* files here need the `-f` again.

## Reproducing

Re-synthesize (needs Quartus Prime Pro 26.1 with Agilex 3 device support):

```bash
cd synth && QUARTUS_BIN=/c/altera_pro/26.1/quartus/bin64 ./run_synth.sh
```

Re-run the analyses (needs a built HAL; `dot` for the diagrams):

```bash
HAL_BASE_PATH=<build> HAL_PY_PATH=<build>/lib PYTHONPATH=<build>/lib:tools \
    python3 examples/agilex3_walkthroughs/06_accumulator_alu/analyze.py
```

Smoke-check the guide's claims (tier 1 needs no HAL at all):

```bash
python3 examples/agilex3_walkthroughs/06_accumulator_alu/check.py
HAL_PY_PATH=<build>/lib python3 .../check.py --require-hal
```
