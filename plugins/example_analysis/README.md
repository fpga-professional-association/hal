# example_analysis

Group sequential gates by the net that drives their clock pin (reference output of tools/new_plugin.py).

Generated by `tools/new_plugin.py`. The contributor walkthrough — what to change,
in what order, and when a C++ plugin is the wrong answer — is
[`documentation/plugin_development.md`](../../documentation/plugin_development.md).

## What it does

Every sequential gate is assigned to the net that drives its clock pin, and the
gates sharing a net become one *structural* clock domain. The analysis reads the
gate type's declared `PinType::clock` rather than matching pin names, so it is
gate-library independent.

Structural is not verified: a clock buffer or a clock gate splits one physical
clock across several nets and therefore across several domains. The findings say
so; do not let a report claim otherwise.

Three things are reported separately, because they are three different answers:

| result | meaning |
| --- | --- |
| a clock domain | these gates share a clock net |
| `unresolved_gates` | the gate has a clock pin that nothing drives |
| `unsupported` | the gate *type* has no clock pin at all — a latch, or a library entry that omits the pin type |

A netlist without a single sequential gate is an **error**, not an empty result.

## Build

```bash
cmake .. -DPL_EXAMPLE_ANALYSIS=ON -DBUILD_TESTS=ON   # or -DBUILD_ALL_PLUGINS=ON
cmake --build . --target example_analysis
ctest -R runTest-example_analysis --output-on-failure
```

## Run

```bash
export HAL_PY_PATH=<build>/lib
python3 plugins/example_analysis/python/run_example_analysis.py <netlist-or-project-dir> \
    --output findings.json
python3 tools/hal_findings validate findings.json
```

From Python:

```python
import hal_py
hal_py.plugin_manager.load_all_plugins()
from hal_plugins import example_analysis

report = example_analysis.analyze(netlist)          # raises RuntimeError with the reason
for domain in report.domains:
    print(domain.clock_net.get_name(), len(domain.gates))
for entry in report.unsupported:
    print(entry.gate_type.get_name(), entry.count, entry.reason)
```

## Capabilities

`capabilities.json` declares what this plugin needs: its plugin dependencies, the
gate-type properties and pin types it reads, the gate libraries it has been
exercised against, and what it costs to run. It is the single source of truth —
CMake compiles it into the plugin (`ExampleAnalysisPlugin.get_capabilities()`) and
copies it to `<build>/share/hal/plugin_capabilities/example_analysis.json`.

```bash
python3 tools/hal_capabilities show  example_analysis
python3 tools/hal_capabilities check example_analysis --netlist <netlist>   # 0 supported, 3 not
python3 tools/hal_capabilities list  --probe --build-dir <build>
```

Keep `dependencies.plugins` in `capabilities.json` and
`ExampleAnalysisPlugin::get_dependencies()` in sync; `list --probe` reports a
mismatch as a defect.
